# 上线计划

## 当前判断

当前项目已经具备继续推进到灰度环境的基础，但还不适合直接面向真实公网用户正式上线。

当前状态：

- 用户侧主要业务链路已接通
- 管理员后台已改为独立登录态和服务端会话
- 管理员操作审计日志已落库
- PostgreSQL 与 S3 兼容对象存储已经接入代码路径

仍然缺少：

- 真实 PostgreSQL 生产实例和数据迁移
- 真实 S3 / COS 存储桶与回源配置
- 接口限流、上传安全复核和敏感操作告警
- 生产部署、监控、备份与回滚体系
- 微信登录 / 微信支付真机联调

## 已完成的 P0

1. 管理员登录与权限体系
   - 已移除前端静态 `admin key`
   - 已增加管理员账号、密码、服务端会话和权限校验
2. 管理员操作审计日志
   - 已记录登录、退出、首页运营修改、首页运营图上传、审核动作
3. 生产方案确定并接入代码路径
   - 生产数据库：PostgreSQL 16
   - 生产对象存储：S3 兼容对象存储，国内优先腾讯云 COS

## 上线前必须完成

### 1. 数据库与存储切换

1. 将 `DB_PROVIDER` 从 `sqlite` 切到 `postgres`
2. 配置 `POSTGRES_URL`
3. 将 `STORAGE_PROVIDER` 从 `local` 切到 `s3`
4. 配置 `S3_*` 相关参数
5. 完成数据迁移、备份和恢复演练

### 2. 安全与权限

1. 增加接口限流
2. 增加上传类型和大小限制复核
3. 补充敏感操作告警
4. 视需要补管理员审计日志查询页

### 3. 微信生产联调

1. 微信登录真机联调
2. 微信支付 v3 下单真机联调
3. 支付回调、退款回调、下载授权联调
4. 微信后台配置合法域名

### 4. 部署与运维

1. 购买服务器
2. 配置域名和 HTTPS
3. 使用 Nginx + PM2 部署
4. 增加日志采集、监控、告警
5. 增加每日数据库与文件备份

## 建议执行顺序

### 第 1 步

- 准备 PostgreSQL
- 准备 S3 / COS 存储桶
- 执行数据迁移

### 第 2 步

- 完成接口限流
- 完成上传安全策略
- 完成告警和运维日志

### 第 3 步

- 真机联调微信登录
- 真机联调微信支付与退款

### 第 4 步

- 配置生产服务器
- 做 staging 验证
- 小范围灰度

## 当前可上线级别

- 可以：团队内测、白名单试用、校内灰度
- 不建议：直接面向公网正式开放注册与支付
