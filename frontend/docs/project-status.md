# 项目状态与执行清单

更新日期：2026-03-31

## 1. 项目现状

### 1.1 项目结构

- `src/`：旧版 Web 原型，仅作为视觉和交互参考，不建议继续作为主工程开发。
- `frontend/`：当前微信小程序前端主工程，基于 Taro React。
- `frontend/src/services`：已拆出 Mock、远程接口协议、运行时切换和 session 管理。
- `frontend/src/hooks`：已形成 `useRequestState`、`usePageRequest`、`useProtectedRequest` 三层请求状态抽象。

### 1.2 当前定位

项目定位已经比较清晰：

- 不是泛校园社交平台
- 不是重课程平台
- 是“竞赛 + 资源 + 组队 + 经验 + AI 导流”的校园成长任务入口

这和 `prd.txt` 的核心方向是一致的。

## 4. 当前主要不足

### 4.1 文案与常量仍需继续集中管理

前端主工程的编码和显性异常文案已经完成收口，但文案集中管理还没有彻底完成。

现状：

- `frontend/` 主工程已统一为 UTF-8
- 已修正确认存在的异常文案和错误分隔符
- 已新增 `constants/enums.ts` 与 `constants/routes.ts`

仍需继续：

- 把更多页面说明文案进一步归拢
- 后端枚举与前端常量保持同步
- 减少页面内散写的业务状态文案

### 4.2 仓库结构仍然混乱

问题：

- 根目录仍保留旧 Web 原型
- README 之前还是无关模板文案
- 新人进入仓库容易跑错工程

建议：

- 明确 `frontend/` 是主工程
- 给旧 Web 原型标注 “legacy prototype”
- 后续可考虑把旧 Web 原型迁到 `legacy-web/` 或单独归档

### 4.3 后端尚未落地

虽然前端已经把接口协议和运行时开关准备好了，但当前仍是前端主导的 Mock 方案。

这意味着：

- 登录不是真实身份
- 搜索不是真实检索
- AI 不是正式模型输出
- 订单、支付、资源领取都没有真实数据链路

### 4.4 业务动作仍偏演示

当前很多动作能点，但还没有真实闭环：

- 收藏
- 报名
- 组队申请与审批
- 点赞 / 评论 / 举报
- 支付与下载
- 上传与审核

### 4.5 工程化还不够

缺失内容：

- 自动化测试
- lint / format 统一规范
- CI
- 发布说明
- 埋点与监控
- 错误上报

## 5. 建议的改进方向

### 5.1 先做“可交付”，不要先做“大而全”

优先交付这五条主链路：

1. 登录
2. 首页推荐
3. 竞赛浏览与详情
4. 资源浏览与详情
5. 组队浏览、发布、申请

### 5.2 文案和业务常量继续集中管理

当前已新增：

- `frontend/src/constants/enums.ts`
- `frontend/src/constants/routes.ts`

下一步建议继续补：

- 页面级公共文案
- 运行模式说明文案
- 受保护页面的统一提示语

### 5.3 详情页继续抽“联动请求”模式

当前详情页仍然直接使用 `useRequestState` 管理主请求和关联请求。

后续可继续抽：

- `useLinkedRequests`
- `useDetailPageData`

把“主详情成功后加载相关推荐 / 关联组队 / 关联资料”也进一步标准化。

### 5.4 先定义后台边界，再做后台

后台不是最后补个页面，而是前台能否持续运营的前提。

建议后台最小集先定义：

- 用户管理
- 竞赛管理
- 资源管理
- 内容审核
- 组队审核
- Banner / 配置位
- 订单管理
